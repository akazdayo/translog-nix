# 設計方針の変更点


この文書は、Observer が基準を保持してプロキシに NarInfo を返す以前の設計から、[新しい設計](design.md)への変更をまとめる。

| 項目 | 以前の設計 | 新しい方針 |
| --- | --- | --- |
| Observer | 上流を観測し、基準を保持してプロキシに返す | 上流を観測し、Transparency Log に記録する。配信は担当しない |
| 基準の取得先 | Observer が保持する基準 | プロキシがローカルに同期・検証したログの最初の有効な記録 |
| 記録がない対象 | Observer が上流を取得・記録してから基準を返す | プロキシが上流から取得して返し、Observer に非同期で観測を依頼する |
| 初回配信 | ログ記録に失敗した未記録の NarInfo は返さない | 記録・同期の完了を待たずに上流の NarInfo を返す |
| ログの扱い | ログの形式・検証方式は今後決定 | Tessera を利用し、プロキシはログを定期的に同期・検証する方針 |
| 変化の通知 | 基準と異なる観測を metrics で通知 | 当面は対象外。将来の拡張とする |

初回はプロキシと Observer が別々に上流へ問い合わせるため、初回に返した内容と後からログに記録された最初の内容が異なる可能性がある。今回の方針では、その差の照合・通知は扱わない。したがって、ログ同期後の基準は一つだが、ログに記録される前の初回配信まで同じ内容を保証するものではない。

Observer への依頼の失敗、ログ同期や検証の失敗、定期再観測の必要性などは未決定事項として残す。詳細と信頼境界は設計書を参照する。
